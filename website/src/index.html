Abstract

Corb is a command-line tool that runs the Pi coding agent inside a Gondolin micro-VM. You choose the directories it can reach, the hosts it can contact, and the Git operations it can perform.

Model credentials stay on the host. Filesystem restrictions apply to every process in the guest. Policy decisions go into one audit log.

Build your first session · Read the boundary

1. Operation

corb run ~/Code/packet-loss --trust-config

Corb boots a VM, mounts the project at /work/packet-loss, and starts Pi in your terminal. Writable mounts write back to the host directory. The first run requires explicit acceptance of the effective configuration.

host                         guest micro-VM
------------------------     -------------------
workspace directories  <---> /work/<name>
filesystem policy            Pi + its processes
network + Git policy   <---- outbound requests
credentials + audit log      secret placeholders

2. Boundaries

  • Network access uses an explicit host allowlist.
  • Model API keys are substituted on the host for permitted destinations.
  • Directories can be writable or read only, with additional rules for individual paths.
  • Git access and GitHub API requests can be restricted by policy.

These controls have specific limits. Read Security and policy before choosing a configuration.

4. Implementation status

EXPERIMENTAL

Corb is run from a source checkout today. It is not yet published to npm. The current runtime launches Pi and reads one global configuration file.

Named workspace files, agent extensions, and configured system-prompt append files are not implemented. The documentation describes the working commands and labels planned behavior explicitly.
