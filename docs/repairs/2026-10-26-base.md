## Git HTTPS cause and repair

All four old Git paths failed: normal Git and `real-git`, each as root and through `dropcap` as uid 1000.
The production CA and gate mount were present. The first TLS 1.3 handshake verified the certificate and fetched the advertisement.
Git's next connection offered the earlier session ticket. The proxy returned a decrypt alert before the next HTTP request.

A native socket reproduction isolated Gondolin's bare `TLSSocket` and asynchronous SNI context setup.
The host used Node 26.12.1 with OpenSSL 4.1.0. The server reported `tls_parse_ctos_psk:bad extension` during resumption.
Passing the leaf context at socket construction restored TLS 1.3 resumption in that reproduction.

The SDK exposes no public context hook at that point. Corb therefore uses a small per-VM adapter for the pinned SDK.
It prepares the destination context and calls `TLSSocket.setKeyCert` before passing encrypted bytes to the SDK.
The adapter checks the SDK version and internal shapes, bounds pending bytes, and drops work after connection cleanup.
It fails the connection if context preparation fails. An SDK upgrade must review this internal adapter.

Both production sessions and the image wrapper use the same repair.
The measured path makes a fresh verified TLS 1.3 handshake when the client offers an earlier ticket.
It keeps certificate verification, TLS versions, ciphers, HTTP versions, policygate, and host policy intact.
The gate also retains the separate Node and curl TLS checks.

The repaired image uses Git `2.52.0-r0`, curl/libcurl `8.23.0-r0`, and OpenSSL libraries `3.5.9-r0`.
All four Git paths complete a public `ls-remote` through the production proxy and gate mount.
Their traces show `OpenSSL verify result: 0` and `SSL certificate verified via OpenSSL.`.
The native TLS regression covers the earlier-session-ticket case with certificate checks enabled.

## Source checks and limits

The issue's stated source facts matched the checkout and measured base. No stated source fact required a scope change.
Three additional interface details shaped the checks:

- APK 3.0.8 rejects `apk fetch name=version` here. The validator fetches by name and requires exact signed version and control identity equality.
- APK records the target architecture for some signed `noarch` packages. The check accepts that compatible normalization and rejects conflicting native architectures.
- Curl 8.23 reports successful verification with a different phrase from 8.22. The gate accepts both measured phrases and rejects missing verification evidence.

The SDK returns a configured VM before its host PID exists. Diagnostics inspect the PID after a real guest command starts.
Its `listSessions()` API is asynchronous. Cleanup awaits it and checks host processes outside the sandbox PID namespace.

Several development candidates stopped before import. None wrote a ref.
One candidate completed HTTPS but failed the new trace assertion because of curl's changed phrase.
Only the final seven-of-seven build counts as success. The historical spike result stays six of seven.

This repair does not publish the canonical default alias. The coordinator controls that later step.
It adds no workspace layers, `corb.sum`, OCI sharing, or services.
Only the x86_64 Docker build and QEMU path were measured. Native image builds and aarch64 were not run.

## TLS cleanup follow-up on 2026-10-26

Independent review found a stale context rejection path.
The earlier adapter let it abort a replacement connection with the same key.
The rejection path now requires the original session and its pending buffer before calling the SDK's abort method.
Active context failures still close their own connection. Stale failures after cleanup or pending buffer overflow have no effect.

Three added regressions cover key reuse, late rejection after overflow, and delayed overflow cleanup.
The host suite passed 1,565 tests across 61 files. Typecheck, lint, and Markdown lint passed.
The earlier image and e2e measurements remain unchanged. This follow-up did not boot VMs or alter canonical refs or assets.
